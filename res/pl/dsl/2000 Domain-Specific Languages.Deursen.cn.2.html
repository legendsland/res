摘要ABSTRACT

领域特定语言利用特定应用领域的固有特性，帮助软件工程提高软件系统的质量与灵活性，并实现按时交付。本综述讨论用于软件系统构建与维护的领域特定语言，涵盖其术语、风险与收益、实例、设计方法和实现技术。此外，本文还选取了领域特定语言方面的 75 篇重要文献，并逐一附上评述。Domain-Specific Languages are used in software engineering in order to enhance quality, flexibility, and timely delivery of software systems, by taking advantage of specific properties of a particular application domain. This survey covers terminology, risks and benefits, examples, design methodologies, and implementation techniques of domain-specific languages as used for the construction and maintenance of software systems. Moreover, it covers an annotated selection of 75 key publications in the area of domain-specific languages.

1　引言1 Introduction

在科学与工程的各个分支中，都可以区分通用方法与专用方法。通用方法为某个领域的许多问题提供一般性解决方案，但这些方案未必最优。专用方法则针对较小的一组问题，提供好得多的解决方案。这种二分在计算机科学中的一种体现，正是本综述的主题：领域特定语言与通用编程语言。In all branches of science and engineering one can distinguish between approaches that are generic and those that are specific. A generic approach provides a general solution for many problems in a certain area, but such a solution may be suboptimal. A specific approach provides a much better solution for a smaller set of problems. One of the incarnations of this dichotomy in computer science is the topic of this survey: domain-specific languages versus generic programming languages.

当然，这不是一个新话题。较早的编程语言 Cobol、Fortran 和 Lisp，最初都是为解决特定领域问题而诞生的专用语言，分别面向商业处理、数值计算和符号处理。它们逐渐演变成了通用语言；与此同时，为边界明确的应用领域提供更专门的语言支持的需求，又一再出现。随着时间推移，人们尝试了以下解决办法：Of course, this is not a new topic. The older programming languages (Cobol, Fortran, Lisp) all came into existence as dedicated languages for solving problems in a certain area (respectively business processing, numeric computation and symbolic processing). Gradually they have evolved into general purpose languages and over and over again the need for more specialized language support to solve problems in well-defined application domains has resurfaced. Over time, the following solutions have been tried:

  • 子程序库包含在界定明确的领域中执行相关任务的子程序，例如微分方程、图形、用户界面和数据库。子程序库是封装可复用领域知识的经典方法。Subroutine libraries contain subroutines that perform related tasks in well-defined domains like, for instance, differential equations, graphics, user-interfaces and databases. The subroutine library is the classical method for packaging reusable domain-knowledge.
  • 面向对象框架与组件框架延续了子程序库的思想。传统库具有扁平结构，由应用程序调用库。而在面向对象框架中，通常由框架掌握控制权，调用应用程序专用代码提供的方法 [42, 32]。Object-oriented frameworks and component frameworks continue the idea of subroutine libraries. Classical libraries have a flat structure, and the application invokes the library. In object-oriented frameworks it is often the case that the framework is in control, and invokes methods provided by the application-specific code [42, 32].
  • 领域特定语言（DSL）是一种小型的、通常具有声明性的语言，其表达能力集中于某个特定问题领域。在许多情况下，DSL 程序会被翻译成对通用子程序库的调用，因此可以把 DSL 看作隐藏该库实现细节的一种手段。A domain-specific language (DSL) is a small, usually declarative, language that offers expressive power focused on a particular problem domain. In many cases, DSL programs are translated to calls to a common subroutine library and the DSL can be viewed as a means to hide the details of that library.

虽然多年来人们已经设计并使用了许多领域特定语言，但对它们的系统研究直到较近时期才开始。本综述梳理这一领域，收录涉及以下主题的研究文献：术语（第 2 节）、风险与机遇（第 3 节）、DSL 实例（第 4 节）、DSL 设计方法（第 5 节）和 DSL 实现策略（第 6 节）。所列论文都附有摘要式评述，评述中又通过交叉引用关联到其他相关论文。Although many domain-specific languages have been designed and used over the years, the systematic study of domain-specific languages has only started more recently. This survey provides an inventory of the field and covers references to research that deals with the following topics: terminology (Section 2), risks and opportunities (Section 3), example DSLs (Section 4), DSL design methodology (Section 5), and DSL implementation strategies (Section 6). The papers listed are annotated with summaries, which in turn are cross-referenced to related papers.

2　术语2 Terminology

究竟什么是领域特定语言，仍有争议。我们提出如下定义：The question what exactly is a domain-specific language is subject to debate. We propose the following definition:

领域特定语言（DSL）是一种编程语言或可执行规约语言；它通过适当的记法与抽象，提供集中于、并且通常局限于某个特定问题领域的表达能力。A domain-specific language (DSL) is a programming language or executable specification language that offers, through appropriate notations and abstractions, expressive power focused on, and usually restricted to, a particular problem domain.

按照这一定义，DSL 的关键特征是其具有针对性的表达能力。The key characteristic of DSLs according to this definition is their focussed expressive power.

这个定义继承了其中一个定义项——“问题领域”——的模糊性。我们不再尝试定义这个难以确定的概念，而是在第 4 节列出并分类说明已经实际构建过 DSL 的一些领域。此外，文献 [70] 有一段有趣的讨论：它对比了人工智能界采用的“领域即现实世界”观点，与系统化软件复用研究界采用的“领域即一组系统”方法。Our definition inherits the vagueness of one of its defining terms: problem domain. Rather than attempting to define this volatile notion as well, we list and categorize a number of domains for which DSLs have actually been built in Section 4. Moreover, we refer to [70], which contains an interesting discussion contrasting a “domain as the real world” point of view as adopted in the artificial intelligence community, with a “domain as a set of systems” approach, as used in the systematic software reuse research community.

DSL 通常很小，只提供有限的一套记法与抽象。文献中也称它们为“微型语言”和“小语言”[7]。但有时它们会将一整门通用语言（GPL）作为子语言，从而在 GPL 的表达能力之外，再提供领域特定的表达能力。这种情形会出现在将 DSL 实现为嵌入式语言时（见第 6 节）。Cobol 和 Fortran 分别针对商业编程和科学编程领域，看起来也可以算作面向特定领域的语言，但通常并不将它们视为 DSL，因为它们并不小，而且表达能力也不局限于这些领域。DSLs are usually small, offering only a restricted suite of notations and abstractions. In the literature they are also called micro-languages and little languages [7]. Sometimes, however, they contain an entire general-purpose language (GPL) as a sublanguage, thus offering domain-specific expressive power in addition to the expressive power of the GPL. This situation occurs when DSLs are implemented as embedded languages (see Section 6). Languages such as Cobol or Fortran, which could be viewed as languages tailored towards the domain of business and scientific programming, respectively, are generally not regarded as DSLs, because they are not small and because their expressive power is not restricted to these domains.

领域特定语言通常具有声明性。因此，它们既可以看作规约语言，也可以看作编程语言。许多 DSL 由 DSL 编译器支持，后者从 DSL 程序生成应用程序。这时，文献中将 DSL 编译器称为“应用生成器”[17]，将 DSL 称为“应用特定语言”。其他 DSL，例如 YACC [7] 或 ASDL [77]，并不面向完整应用程序的编程或规约，而是用于生成库或组件。此外，还有一些 DSL 的执行结果是生成文档（TeX）或图像（PIC [7]）。用于构建商业数据处理系统的 DSL，通常称为第四代语言（4GL）。Domain-specific languages are usually declarative. Consequently, they can be viewed as specification languages, as well as programming languages. Many DSLs are supported by a DSL compiler which generates applications from DSL programs. In this case, the DSL compiler is referred to as application generator in the literature [17], and the DSL as application-specific language. Other DSLs, such as YACC [7] or ASDL [77], are not aimed at programming (specifying) complete applications, but rather at generating libraries or components. Also, DSLs exist for which execution consists in generating documents (TEX), or pictures (PIC [7]). A common term for DSLs geared towards building business data processing systems is 4th Generation Language (4GL).

与领域特定编程相关的还有最终用户编程，即最终用户利用宏语言或脚本语言完成简单编程任务。一个典型例子，是使用 Excel 宏语言进行电子表格编程。Related to domain-specific programming is end-user programming, which happens when end-users perform simple programming tasks using a macro or scripting language. A typical example is spreadsheet programming using the Excel macro-language.

3　风险与机遇3 Risks and Opportunities

在软件工程中采用 DSL 方法，既有风险，也有机遇。设计良好的 DSL 能够在两者之间取得恰当平衡。DSL 的收益包括：Adopting a DSL approach to software engineering involves both risks and opportunities. The well-designed DSL manages to find the proper balance between these two. The benefits of DSLs include:

  • DSL 允许用问题领域自身的术语，并在该领域的抽象层次上表达解决方案。因此，领域专家自己就能理解、验证、修改，甚至经常能够开发 DSL 程序。DSLs allow solutions to be expressed in the idiom and at the level of abstraction of the problem domain. Consequently, domain experts themselves can understand, validate, modify, and often even develop DSL programs.
  • DSL 程序简洁，在很大程度上具有自说明性，而且可以为不同目的复用 [50]。DSL programs are concise, self-documenting to a large extent, and can be reused for different purposes [50].
  • DSL 可以提高生产率、可靠性、可维护性 [24, 47] 和可移植性 [38]。DSLs enhance productivity, reliability, maintainability [24, 47], and portability [38].
  • DSL 体现了领域知识，因此能够保存并复用这些知识。DSLs embody domain knowledge, and thus enable the conservation and reuse of this knowledge.
  • DSL 允许在领域层面进行验证与优化 [6, 13, 55]。DSLs allow validation and optimization at the domain level [6, 13, 55].
  • DSL 可以通过文献 [71] 等方法提高可测试性。DSLs improve testability following approaches such as [71].

使用 DSL 的缺点包括：The disadvantages of the use of a DSL are:

  • 设计、实现和维护 DSL 的成本。The costs of designing, implementing and maintaining a DSL.
  • 培训 DSL 用户的成本。The costs of education for DSL users.
  • 可用 DSL 的数量有限 [49]。The limited availability of DSLs [49].
  • 难以为 DSL 确定恰当的适用范围。The difficulty of finding the proper scope for a DSL.
  • 难以在领域专用性与通用编程语言构造之间取得平衡。The difficulty of balancing between domain-specificity and general-purpose programming language constructs.
  • 与手工编写的软件相比，可能损失执行效率。The potential loss of efficiency when compared with hand-coded software.

文献 [20, 22, 47] 比较了 DSL 方法与其他软件生成方法。文献 [24] 从软件维护的角度分析 DSL 的成本与收益。文献 [49] 将 DSL 列为软件复用的主要方法之一，并与其他复用技术作了详细比较。Comparisons of the DSL approach to other approaches to software generation are made in [20, 22, 47]. In [24] the costs and benefits of DSLs are analyzed from the perspective of software maintenance. In [49], DSLs are categorized as one of the main approaches to software reuse, and a detailed comparison is made to other reuse techniques.

5　DSL 设计方法5 DSL Design Methodology

开发领域特定语言通常包括以下步骤（见 [17, 24]）：The development of a domain-specific language typically involves the following steps (see [17, 24]):

  • 分析
    （1）确定问题领域。（2）收集该领域的一切相关知识。（3）将这些知识归纳为少量语义概念及其操作。（4）设计一种能够简洁描述该领域应用程序的 DSL。    Analysis (1) Identify the problem domain. (2) Gather all relevant knowledge in this domain. (3) Cluster this knowledge in a handful of semantic notions and operations on them. (4) Design a DSL that concisely describes applications in the domain.
  • 实现
    （5）构建一个实现这些语义概念的库。（6）设计并实现编译器，将 DSL 程序翻译成一系列库调用。    Implementation (5) Construct a library that implements the semantic notions. (6) Design and implement a compiler that translates DSL programs to a sequence of library calls.
  • 使用
    （7）为所有需要的应用编写 DSL 程序，并进行编译。    Use (7) Write DSL programs for all desired applications and compile them.

分析步骤（1）至（4）的目标，是透彻理解背后的应用领域。研究如何对领域建模的领域分析，为获得这种理解提供了指导。按照文献 [58]，领域分析人员研究一组看起来“相似”的系统的需要与需求。Neighbors 强调，只有曾为同一问题领域的不同客户构建过许多系统的人，才能完成这项工作。领域分析人员与系统分析人员相似，但其目标是支持一族相关系统的开发，而不是仅仅支持一次性的单独产品 [75]。The aim of the analysis steps (1) through (4) is to build up a thorough understanding of the underlying application domain. Guidelines for acquiring such an understanding are provided by the research area of domain analysis which investigates ways of modeling domains. Following [58], a domain analyst is a person who examines the needs and requirements of a collection of systems which seem “similar”. Neighbors emphasizes that this is work that only can be done by a person who has built many systems for different customers in the same problem area. The domain analyst is like a systems analyst, except that the goal is to support the development of families of related systems, not just one-of-a-kind productions [75].

领域工程 [3] 指系统地对领域建模的活动。它源于软件复用研究，可用于构建领域特定的可复用库、框架或语言。文献 [20, 第 3 章] 提供了较新的领域工程综述。目前已有多种领域工程方法，其中最著名的是 ODM（组织领域建模 [69, 70]）、FODA（面向特征的领域分析 [45]）和 DSSA（领域特定软件架构 [75]）。Domain engineering [3] refers to the activity of systematically modeling domains. Domain engineering originates from research in the area of software reuse, and can be used when constructing domain-specific reusable libraries, frameworks or languages. A recent domain engineering survey is provided by [20, Chapter 3]. Several domain engineering methodologies exists, of which ODM (Organizational Domain Modeling [69, 70]), FODA (Feature-Oriented Domain Analysis [45]), and DSSA (Domain-Specific Software Architectures [75]) are best known.

与领域工程密切相关的是程序族概念，即一组相似程序 [52, 18]。朗讯采用一种系统化的程序族开发方法——面向族的抽象、规约与翻译（FAST）方法，已经成功应用于 25 个以上的不同领域 [18]。程序族又与软件产品线相关。软件产品线强调所有产品共有的特征，并聚焦于选定市场的需求 [21, 53, 78]。Strongly related to domain engineering is the notion of program families which are sets of similar programs [52, 18]. At Lucent, a systematic approach to the development of families is in use, the Family-Oriented Abstraction, Specification and Translation (FAST) approach, which has been successfully applied to over 25 different domains [18]. Program families are in turn related to software product lines. These emphasize features shared by all products, and are focused on the needs of a selected market [21, 53, 78].

开发 DSL 的一个前提，是具备成熟的领域知识。因此，DSL 被视为面向对象应用框架演化的最终、最成熟阶段 [66, 22]。同样，在为某个领域开发 DSL 时，实现了领域概念的遗留系统也会有所帮助 [70]。可以使用逆向工程技术，从这类系统中提炼领域知识；文献 [16, 25] 对这些技术作了概述。A prerequisite to developing a DSL is mature domain knowledge. For that reason, a DSL is viewed as the final and most mature phase of the evolution of an object-oriented application framework [66, 22]. For the same reason, the existence of legacy systems implementing domain concepts will be of use when developing a DSL for that domain [70]. Reverse engineering techniques may be used to distill domain knowledge from such legacy systems — an overview of such techniques is provided by [16, 25].

6　DSL 实现6 DSL Implementation

上一节的实现步骤（5）和（6），可以采用以下几种方法完成：The implementation steps (5) and (6) of the previous section can be carried out using several approaches:

解释或编译Interpretation or compilation

这是实现新语言的经典方法。可以使用标准编译器工具 [1, 7]，也可以采用专门用于实现 DSL 的工具，例如 Draco [58]、ASF+SDF [23]、Kephera [31]、Kodiyak [38]、基于选择的设计 [62] 或 InfoWiz [56]。This is the classical approach to implementing a new language. Standard compiler tools [1, 7] can be used, or tools dedicated to the implementation of DSLs like Draco [58], ASF+SDF [23], Kephera [31], Kodiyak [38], design by selection [62], or InfoWiz [56].

构建编译器或解释器的主要优点，是实现完全针对 DSL 量身定做，无须在记法、原语等方面作出妥协。错误检测、静态分析和优化也可以在领域层面进行，例如采用文献 [13] 中的效应系统。The main advantage of building a compiler or interpreter is that the implementation is completely tailored towards the DSL and no concessions are necessary regarding notation, primitives and the like. Also, error detection, static analysis, and optimizations can be done at the domain level, for example using an effect system as in [13].

显然，一个重要问题是：从零构建这类编译器或解释器的成本较高，而且难以复用其他 DSL 的实现。不过，一些 DSL 工具集（例如 InfoWiz [56]）正是专门为克服这些问题而设计的。Clearly, an important problem is the cost of building such a compiler or interpreter from scratch, and the lack of reuse from other (DSL) implementations, although some DSL tool sets (for example InfoWiz [56]) are particularly designed to overcome such problems.

不必从零实现 DSL 的另一种办法，是扩展某门既有基础语言。例如，文献 [6] 描述了如何为一门通用语言的受限版本加入领域特定构造。其主要优点是，基础语言的所有特性仍然可用，无须重新实现。As an alternative to implementing a DSL from scratch, a DSL can be implemented by extending a given base language. For instance, [6] describes an extension of (a restricted version of) a general-purpose language with domain-specific constructs. The main advantage of this approach is that all features of the base language remain available and need not be re-implemented.

实现基础语言的领域特定扩展时，可以通过三种不同方式复用基础语言的实现：When implementing domain-specific extensions of a base language, the implementation of the base language can be reused in three different ways:

嵌入式语言／领域特定库Embedded languages / domain-specific libraries

这种方法利用现有机制，例如函数定义或支持用户定义语法的运算符，构建领域特定操作库。它使用基础语言的语法机制，表达该领域的惯用概念。In this approach, existing mechanisms such as definitions for functions or operators with user-defined syntax are used to build a library of domain-specific operations. The syntactic mechanisms of the base language are used to express the idiom of the domain.

其优点是，可以原封不动地复用基础语言的编译器或解释器来支持 DSL。主要限制在于，基础语言的语法机制能够表达什么。在许多情况下，必须牺牲最适合领域的记法，以适应基础语言的限制。典型例子有文献 [61] 中嵌入 Haskell 的机器人控制语言，以及文献 [44] 中嵌入 ML 的类 PIC 绘图语言。“领域特定嵌入式语言”这一概念由 Hudak 提出 [40]。An advantage of this approach is that the compiler or interpreter of the base language is reused as is for the DSL. The main limitation is in the expressiveness of the syntactic mechanisms in the base language. In many cases, the optimal domain-specific notation has to be compromised to fit the limitations of the base language. Typical examples of this approach are [61] (a robot control language embedded in Haskell) and [44] (a PIC-like drawing language embedded in ML). The concept of domain-specific embedded language was coined by Hudak [40].

预处理或宏处理Preprocessing or macro processing

这种方法使用预处理器，将新构造翻译成基础语言中的语句。它的主要优点是简单；主要缺点是，静态检查与优化并非在领域层面进行。因此，生成的代码容易出错，用户得到的错误反馈处于基础语言层面，或者直到运行时才出现。In this approach the new constructs are translated to statements in the base language by a preprocessor. The main advantage of this approach is simplicity. Its main disadvantage is that static checking and optimization are not done at the domain level. Consequently, generated code is error prone, and the user is provided with feedback on these errors at the level of the base language, or only at run-time.

可扩展的编译器或解释器Extensible compiler or interpreter

这种方法与前一种相似，但预处理阶段被集成到编译器内部。其优点是，可以进行更多类型检查和更好的优化。文献 [30, 74] 采用了这一方法。Tcl [59] 解释器也是一个典型例子：人们已经为数十个领域扩展了它。This approach is similar to the previous one, but the preprocessing phase is now integrated in the compiler. The advantage is that more type checking and better optimization is possible. This approach is taken by [30, 74]. The Tcl [59] interpreter is also a prime example: it has been extended for dozens of domains.

除了构建专用 DSL 编译器或解释器，或复用底层基础语言的实现，还可以采用其他实现技术。例如，在面向方面编程 [46] 中，用 DSL 描述系统行为中与主要功能正交的某个方面，再由方面编织器生成领域特定代码，并将其与主代码合并。Apart from building a dedicated DSL compiler or interpreter, or reusing the implementation of an underlying base language, other implementation techniques may be used. For instance, in aspect-oriented programming [46] a DSL is used to describe an aspect of a system’s behavior that is orthogonal to its main functionality. An aspect weaver is then used to generate domain-specific code and merge it with the main code.
