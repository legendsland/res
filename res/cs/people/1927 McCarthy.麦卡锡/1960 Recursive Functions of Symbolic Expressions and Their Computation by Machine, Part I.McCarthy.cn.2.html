1 Introduction

A programming system called LISP (for LISt Processor) has been developed for the IBM 704 computer by the Artificial Intelligence group at M.I.T. The system was designed to facilitate experiments with a proposed system called the Advice Taker, whereby a machine could be instructed to handle declarative as well as imperative sentences and could exhibit “common sense” in carrying out its instructions. The original proposal [1] for the Advice Taker was made in November 1958. The main requirement was a programming system for manipulating expressions representing formalized declarative and imperative sentences so that the Advice Taker system could make deductions.

在开发过程中，LISP 系统经历了几个简化阶段，最终建立在一种方案之上，用来表示某类符号表达式上的偏递归函数。这种表示独立于 IBM 704，也独立于任何其他电子计算机。因此，现在看来，从称为 S 表达式的一类表达式和称为 S 函数的函数出发，来阐述这套系统是合适的。

In the course of its development the LISP system went through several stages of simplification and eventually came to be based on a scheme for representing the partial recursive functions of a certain class of symbolic expressions. This representation is independent of the IBM 704 computer, or of any other electronic computer, and it now seems expedient to expound the system by starting with the class of expressions called S-expressions and the functions called S-functions.

e. 函数与形式

e. Functions and Forms

在数学中，数理逻辑以外的领域通常并不严格使用“函数”一词，而把 y² + x 之类的形式也称为函数。由于后面我们要对表示函数的表达式进行计算，因此需要区分函数与形式，并用一种记法表达这种区别。Church [3] 给出了这种区分及其描述记法，我们的记法与之只有细微差别。

It is usual in mathematics—outside of mathematical logic—to use the word “function” imprecisely and to apply it to forms such as y² + x. Because we shall later compute with expressions for functions, we need a distinction between functions and forms and a notation for expressing this distinction. This distinction and a notation for describing it, from which we deviate trivially, is given by Church [3].

设 f 是表示两个整数变量的函数的表达式。那么写 f(3,4) 应当有意义，而且该表达式的值应当确定。表达式 y² + x 不满足这一要求；y² + x(3,4) 不是惯用记法，如果试图定义它，我们也无法确定其值应为 13 还是 19。Church 把 y² + x 这样的表达式称为形式。如果能确定形式中出现的变量，与所需函数的有序实参列表之间的对应关系，就能把形式转变为函数。这由 Church 的 λ 记法来实现。

Let f be an expression that stands for a function of two integer variables. It should make sense to write f(3, 4) and the value of this expression should be determined. The expression y²+x does not meet this requirement; y²+x(3, 4) is not a conventional notation, and if we attempted to define it we would be uncertain whether its value would turn out to be 13 or 19. Church calls an expression like y² + x, a form. A form can be converted into a function if we can determine the correspondence between the variables occurring in the form and the ordered list of arguments of the desired function. This is accomplished by Church’s λ-notation.

若 E 是变量 x₁，……，xₙ 的一个形式，则 λ((x₁，……，xₙ),E) 表示一个 n 元函数。它的值通过按顺序将实参代入 E 中的 x₁，……，xₙ，再对所得表达式求值来确定。例如，λ((x,y),y² + x) 是二元函数，而且 λ((x,y),y² + x)(3,4) = 19。

If E is a form in variables x1, · · ·, xn, then λ((x1, · · · , xn), E) will be taken to be the function of n variables whose value is determined by substituting the arguments for the variables x1, · · · , xn in that order in E and evaluating the resulting expression. For example, λ((x, y), y² + x) is a function of two variables, and λ((x, y), y² + x)(3, 4) = 19.

λ 表达式变量列表中的变量是哑变量或约束变量，类似于定积分中的积分变量。也就是说，只要对某个变量的每次出现都作相同更改，而且不把原来不同的两个变量改成相同变量，就可以更改函数表达式中约束变量的名字，而不改变表达式的值。因此，λ((x,y),y² + x)、λ((u,v),v² + u) 和 λ((y,x),x² + y) 表示同一个函数。

The variables occurring in the list of variables of a λ-expression are dummy or bound, like variables of integration in a definite integral. That is, we may change the names of the bound variables in a function expression without changing the value of the expression, provided that we make the same change for each occurrence of the variable and do not make two variables the same that previously were different. Thus λ((x, y), y² + x), λ((u, v), v² + u) and λ((y, x), x² + y) denote the same function.

我们将经常使用这样一些表达式：其中有些变量被 λ 约束，另一些则没有。这样的表达式可以看作定义了一个带参数的函数。未被约束的变量称为自由变量。

We shall frequently use expressions in which some of the variables are bound by λ’s and others are not. Such an expression may be regarded as defining a function with parameters. The unbound variables are called free variables.

一种能够充分区分函数与形式的记法，可以无歧义地处理以函数为对象的函数。在这里举例会偏离主题太远，不过后文将使用以函数为实参的函数。

组合用 λ 表达式或任何其他含变量的记法描述的函数时，会出现困难，因为不同的约束变量可能用同一个符号表示。这称为约束变量冲突。有一种使用称为组合子的运算符的记法，可以不借助变量来组合函数。遗憾的是，对于有实际意义的函数组合，其组合子表达式往往冗长而难以阅读。

This is called collision of bound variables. There is a notation involving operators that are called combinators for combining functions without the use of variables. Unfortunately, the combinatory expressions for interesting combinations of functions tend to be lengthy and unreadable.

在 LISP 编程系统中，符号的关联表所包含的内容，比前面各节所述数学系统所要求的更多。事实上，任何希望与该符号关联的信息都可以放入关联表。这些信息可以包括：打印名，即在机器外表示该符号的字母与数字串；若符号表示数字，则包括其数值；若符号在某种意义上充当另一 S 表达式的名字，则包括该 S 表达式；若符号表示一个具有机器语言子程序的函数，则包括该例程的位置。这意味着，机器系统中的原始实体，比前面数学系统各节所描述的更多。

In the LISP programming system we put more in the association list of a symbol than is required by the mathematical system described in the previous sections. In fact, any information that we desire to associate with the symbol may be put on the association list. This information may include: the print name, that is, the string of letters and digits which represents the symbol outside the machine; a numerical value if the symbol represents a number; another S-expression if the symbol, in some way, serves as a name for it; or the location of a routine if the symbol represents a function for which there is a machine-language subroutine. All this implies that in the machine system there are more primitive entities than have been described in the sections on the mathematical system.

目前只介绍如何在关联表中表示打印名，使程序在读入或打印时，能够在穿孔卡片、磁带或印刷页面上的信息，与机器内部的表结构之间建立对应。符号 DIFFERENTIATE 的关联表有一段如图 4 所示。这里 pname 是一个符号，表示该关联表所属符号的打印名结构挂接在关联表的下一个字上。图的第二行是一个由三个字组成的列表。每个字的地址字段都指向一个包含六个 6 位字符的字。最后一个字用一种不代表计算机可打印字符的 6 位组合补齐。请记住，IBM 704 的字长为 36 位，每个可打印字符用 6 位表示。包含字符信息的字的存在，意味着关联表本身并不表示 S 表达式，而且只有某些处理 S 表达式的函数在关联表内部有意义。

c. 空闲存储链表

c. Free-Storage List

在任意时刻，为表结构保留的内存中，只有一部分实际用于存储 S 表达式。其余存储单元，在我们的系统中最初约为 15,000 个，被组织成一个称为空闲存储链表的单一列表。程序中的一个特定寄存器 FREE，存放该列表第一个存储单元的位置。当需要一个字来构造额外的表结构时，就取走空闲存储链表中的第一个字，并把 FREE 寄存器中的数值改成链表中第二个字的位置。用户无需编程把存储单元归还到空闲存储链表。

At any given time only a part of the memory reserved for list structures will actually be in use for storing S-expressions. The remaining registers (in our system the number, initially, is approximately 15,000) are arranged in a single list called the free-storage list. A certain register, FREE, in the program contains the location of the first register in this list. When a word is required to form some additional list structure, the first word on the free-storage list is taken and the number in register FREE is changed to become the location of the second word on the free-storage list. No provision need be made for the user to program the return of registers to the free-storage list.

归还过程自动进行，大致如下。本文必须对这一过程作简化描述。程序中有一组固定的基址寄存器，包含程序可以访问的表结构的位置。当然，由于表结构会分支，因此可能涉及任意数量的存储单元。程序可访问的每个存储单元，都能够从一个或多个基址寄存器出发，通过一串 car 和 cdr 操作到达。当某个基址寄存器的内容改变时，它原来指向的存储单元，可能不再能从任何基址寄存器通过 car–cdr 链到达。这样的存储单元可以认为已被程序遗弃，因为任何可能的程序都无法再找到它的内容；因此，其内容已无意义，我们希望把它收回空闲存储链表。这个过程按如下方式发生。

This return takes place automatically, approximately as follows (it is necessary to give a simplified description of this process in this report): There is a fixed set of base registers in the program which contains the locations of list structures that are accessible to the program. Of course, because list structures branch, an arbitrary number of registers may be involved. Each register that is accessible to the program is accessible because it can be reached from one or more of the base registers by a chain of car and cdr operations. When the contents of a base register are changed, it may happen that the register to which the base register formerly pointed cannot be reached by a car −cdr chain from any base register. Such a register may be considered abandoned by the program because its contents can no longer be found by any possible program; hence its contents are no longer of interest, and so we would like to have it back on the free-storage list. This comes about in the following way.

在程序耗尽空闲存储之前，什么也不发生。当需要一个空闲存储单元，而空闲存储链表中已经没有剩余单元时，就启动一次回收7周期。

Nothing happens until the program runs out of free storage. When a free register is wanted, and there is none left on the free-storage list, a reclamation7 cycle starts.

首先，程序找出所有从基址寄存器可达的存储单元，并把它们的符号位改为负。具体做法是从每个基址寄存器出发，把所有能通过 car–cdr 链到达的存储单元的符号位改掉。如果过程中遇到一个符号位已经为负的存储单元，就认为它此前已经到达过。

First, the program finds all registers accessible from the base registers and makes their signs negative. This is accomplished by starting from each of the base registers and changing the sign of every register that can be reached from it by a car −cdr chain. If the program encounters a register in this process which already has a negative sign, it assumes that this register has already been reached.

所有可达存储单元的符号位都改变之后，程序遍历为表结构保留的内存区域，把上一步中符号位未改变的所有存储单元放回空闲存储链表，并把可达存储单元的符号位重新改为正。

After all of the accessible registers have had their signs changed, the program goes through the area of memory reserved for the storage of list structures and puts all the registers whose signs were not changed in the previous step back on the free-storage list, and makes the signs of the accessible registers positive again.

这一过程完全自动进行，因此比要求程序员自行跟踪和清除无用列表的系统更方便。其效率取决于可达列表不要接近耗尽全部可用内存。这是因为回收过程需要数秒钟；为了避免程序把大部分时间都花在回收上，每次回收至少应向空闲存储链表补充数千个存储单元。

This process, because it is entirely automatic, is more convenient for the programmer than a system in which he has to keep track of and erase unwanted lists. Its efficiency depends upon not coming close to exhausting the available memory with accessible lists. This is because the reclamation process requires several seconds to execute, and therefore must result in the addition of at least several thousand registers to the free-storage list if the program is not to spend most of its time in reclamation.

d. 计算机中的初等 S 函数

d. Elementary S-Functions in the Computer

下面介绍 atom、=、car、cdr 和 cons 在计算机中的表示。S 表达式通过表示它的字的位置，传递给表示函数的程序；程序也以同样形式给出 S 表达式结果。

We shall now describe the computer representations of atom, = , car, cdr, and cons. An S-expression is communicated to the program that represents a function as the location of the word representing it, and the programs give S-expression answers in the same form.

atom。如前所述，表示原子符号的字，其地址字段中包含一个特殊常量。atom 被编写为检查该字段的开放子程序。除非 M 表达式 atom[e] 作为条件表达式中的条件出现，否则测试结果会生成符号 T 或 F。对于条件表达式，则使用条件转移，不生成符号 T 或 F。

atom. As stated above, a word representing an atomic symbol has a special constant in its address part: atom is programmed as an open subroutine that tests this part. Unless the M-expression atom[e] occurs as a condition in a conditional expression, the symbol T or F is generated as the result of the test. In case of a conditional expression, a conditional transfer is used and the symbol T or F is not generated.

eq。eq[e;f] 的程序检验两个字的位置在数值上是否相等。之所以可行，是因为每个原子符号只有一个关联表。与 atom 一样，结果要么是条件转移，要么是符号 T 或 F 之一。

eq. The program for eq[e; f] involves testing for the numerical equality of the locations of the words. This works because each atomic symbol has only one association list. As with atom, the result is either a conditional transfer or one of the symbols T or F.

car。计算 car[x]，就是取得存储单元 x 的地址字段内容。这基本上由一条指令 CLA 0,i 完成：实参位于变址寄存器中，结果出现在累加器的地址字段。我们认为，函数从何处取得实参、把结果放到何处，都应在函数定义中规定；程序员或编译器负责插入必要的数据传送指令，使一次计算的结果处于下一次计算所需的位置。“car”是“存储单元地址字段的内容”的助记缩写。

car. Computing car[x] involves getting the contents of the address part of register x. This is essentially accomplished by the single instruction CLA 0, i, where the argument is in index register, and the result appears in the address part of the accumulator. (We take the view that the places from which a function takes its arguments and into which it puts its results are prescribed in the definition of the function, and it is the responsibility of the programmer or the compiler to insert the required datamoving instructions to get the results of one calculation in position for the next.) (“car” is a mnemonic for “contents of the address part of register.”)

cdr。cdr 的处理方式与 car 相同，只是结果出现在累加器的减量字段中。“cdr”表示“存储单元减量字段的内容”。

cdr. cdr is handled in the same way as car, except that the result appears in the decrement part of the accumulator (“cdr” stands for “contents of the decrement part of register.”)

cons。cons[x;y] 的值必须是某个存储单元的位置，该单元的地址字段和减量字段分别包含 x 和 y。计算机中可能不存在这样的单元；即使存在，查找它也很耗时。实际做法是，从空闲存储链表中取出第一个可用单元，分别把 x 和 y 放入其地址字段和减量字段，并把所取单元的位置作为函数值。“cons”是“construct”（构造）的缩写。

cons. The value of cons[x; y] must be the location of a register that has x and y in its address and decrement parts, respectively. There may not be such a register in the computer and, even if there were, it would be time-consuming to find it. Actually, what we do is to take the first available register from the free-storage list, put x and y in the address and decrement parts, respectively, and make the value of the function the location of the register taken. (“cons” is an abbreviation for “construct.”)

空闲存储链表耗尽时，由 cons 子程序启动回收。在目前使用的系统版本中，cons 由封闭子程序表示；在编译版本中，cons 是开放的。

It is the subroutine for cons that initiates the reclamation when the free-storage list is exhausted. In the version of the system that is used at present cons is represented by a closed subroutine. In the compiled version, cons is open.

e. 用程序表示 S 函数

e. Representation of S-Functions by Programs

无论手工编译还是使用编译器程序，由 car、cdr 和 cons 复合而成的函数都很容易编译。条件表达式也没有什么困难，只需保证编译后只计算必要的 p 和 e。不过，编译递归函数时会出现问题。

The compilation of functions that are compositions of car, cdr, and cons, either by hand or by a compiler program, is straightforward. Conditional expressions give no trouble except that they must be so compiled that only the p’s and e’s that are required are computed. However, problems arise in the compilation of recursive functions.

一般而言，稍后会讨论一种例外，递归函数的例程会把自身当作子程序使用。例如，subst[x;y;z] 的程序使用自身作为子程序，计算对子表达式 car[z] 和 cdr[z] 进行替换的结果。计算 subst[x;y;cdr[z]] 时，必须把先前计算 subst[x;y;car[z]] 的结果保存在临时存储单元中。然而，subst 在计算 subst[x;y;cdr[z]] 时，可能也需要使用同一个存储单元。这个潜在冲突由使用公共下推表8的 SAVE 和 UNSAVE 例程解决。进入递归函数例程时，先进入 SAVE 例程，请求保存一组给定的连续存储单元。为此保留了一块称为公共下推表的存储区。SAVE 例程有一个索引，指出下推表中已有多少存储单元正在使用。它把需要保存的单元内容移到下推表中最前面的未用单元，推进索引，然后返回调用程序。调用程序随后可以自由地把这些单元用作临时存储。例程退出前调用 UNSAVE，从下推表恢复临时单元的内容，并回退索引。用编程术语来说，这些约定使递归子程序对临时存储单元具有透明性。

In general (we shall discuss an exception), the routine for a recursive function uses itself as a subroutine. For example, the program for subst[x; y; z] uses itself as a subroutine to evaluate the result of substituting into the subexpressions car[z] and cdr[z]. While subst[x; y; cdr[z]] is being evaluated, the result of the previous evaluation of subst[x; y; car[z]] must be saved in a temporary storage register. However, subst may need the same register for evaluating subst[x; y; cdr[z]]. This possible conflict is resolved by the SAVE and UN- SAVE routines that use the public push-down list 8. The SAVE routine is entered at the beginning of the routine for the recursive function with a request to save a given set of consecutive registers. A block of registers called the public push-down list is reserved for this purpose. The SAVE routine has an index that tells it how many registers in the push-down list are already in use. It moves the contents of the registers which are to be saved to the first unused registers in the push-down list, advances the index of the list, and returns to the program from which control came. This program may then freely use these registers for temporary storage. Before the routine exits it uses UNSAVE, which restores the contents of the temporary registers from the push-down list and moves back the index of this list. The result of these conventions is described, in programming terminology, by saying that the recursive subroutine is transparent to the temporary storage registers.

5 符号表达式函数的另一种形式体系

5 Another Formalism for Functions of Symbolic Expressions

有多种定义符号表达式函数的方法，与我们采用的系统十分相似。每种方法都涉及三个基本函数、条件表达式和递归函数定义，但对应于 S 表达式的表达式类不同，函数的精确定义也不同。下面介绍其中一个变体，称为线性 LISP。

There are a number of ways of defining functions of symbolic expressions which are quite similar to the system we have adopted. Each of them involves three basic functions, conditional expressions, and recursive function definitions, but the class of expressions corresponding to S-expressions is different, and so are the precise definitions of the functions. We shall describe one of these variants called linear LISP.

L 表达式定义如下：

The L-expressions are defined as follows:

  1. 规定一个有限的允许字符表。

    A finite list of characters is admitted.

  2. 由允许字符构成的任意字符串都是 L 表达式。其中包括以 Λ 表示的空字符串。

    Any string of admitted characters in an L-expression. This includes the null string denoted by Λ.

字符串上有三个函数：

There are three functions of strings:

  1. first[x] 是字符串 x 的第一个字符。

    first[x] is the first character of the string x.

    first[Λ] 未定义。例如：first[ABC] = A。

    first[Λ] is undefined. For example: first[ABC] = A

  2. rest[x] 是从字符串中删除第一个字符后剩余的字符串。

    rest[x] is the string of characters which remains when the first character of the string is deleted.

    rest[Λ] 未定义。例如：rest[ABC] = BC。

    rest[Λ] is undefined. For example: rest[ABC] = BC.

  3. combine[x;y] 是把字符 x 加到字符串 y 前面所形成的字符串。例如：combine[A;BC] = ABC。

    combine[x; y] is the string formed by prefixing the character x to the string y. For example: combine[A; BC] = ABC

字符串上有三个谓词：

There are three predicates on strings:

  1. char[x]：x 是单个字符。

    char[x], x is a single character.

  2. null[x]：x 是空字符串。

    null[x], x is the null string.

  3. x = y，在 x 和 y 都是字符时有定义。

    x = y, defined for x and y characters.

线性 LISP 的优点是，不像 LISP 中的圆括号、点和逗号那样，任何字符都没有特殊作用。这使它能够对所有可以线性书写的表达式进行计算。缺点是，提取子表达式是一项相当复杂的操作，而不是初等操作。在 线性 LISP 中编写对应于 LISP 基本函数的函数并不困难，因此从数学上说，线性 LISP 包含 LISP。事实证明，在 线性 LISP 中编写更复杂的操作时，这也是最方便的方法。不过，如果这些函数要用计算机例程表示，LISP 本质上更快。

The advantage of linear LISP is that no characters are given special roles, as are parentheses, dots, and commas in LISP. This permits computations with all expressions that can be written linearly. The disadvantage of linear LISP is that the extraction of subexpressions is a fairly involved, rather than an elementary, operation. It is not hard to write, in linear LISP, functions that correspond to the basic functions of LISP, so that, mathematically, linear LISP includes LISP. This turns out to be the most convenient way of programming, in linear LISP, the more complicated manipulations. However, if the functions are to be represented by computer routines, LISP is essentially faster.

6 流程图与递归

6 Flowcharts and Recursion

通常形式的计算机程序和递归函数定义，在计算能力上都是通用的，因此展示它们之间的关系很有意义。本报告此前的内容讨论了如何把递归符号函数翻译成计算机程序。本节说明如何反过来做，至少在原理上如此。

Since both the usual form of computer program and recursive function definitions are universal computationally, it is interesting to display the relation between them. The translation of recursive symbolic functions into computer programs was the subject of the rest of this report. In this section we show how to go the other way, at least in principle.

计算过程中，机器在任意时刻的状态由若干变量的值给出。把这些变量组合成向量 ξ。考虑一个只有一个入口和一个出口的程序块。它定义了某个把一种机器配置变成另一种配置的函数 f，而且本质上也由该函数定义；即 f 具有 ξ′ = f(ξ) 的形式。我们把 f 称为该程序块的关联函数。现在用决策元素 π 把若干这样的程序块组合成程序，决策元素在每个块完成后决定接下来进入哪个块。同时，仍要求整个程序只有一个入口和一个出口。

The state of the machine at any time during a computation is given by the values of a number of variables. Let these variables be combined into a vector ξ. Consider a program block with one entrance and one exit. It defines and is essentially defined by a certain function f that takes one machine configuration into another, that is, f has the form ξ′ = f(ξ). Let us call f the associated function of the program block. Now let a number of such blocks be combined into a program by decision elements π that decide after each block is completed which block will be entered next. Nevertheless, let the whole program still have one entrance and one exit.
